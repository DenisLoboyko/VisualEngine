# 📦 Руководство по оптимизации размера проекта

## Проблема
После разработки проект занимал **499 МБ в ZIP**, в то время как Godot занимает только 81 МБ.

## Решение
Удалены временные файлы и кэши, которые не нужны в архиве.

## Результаты
| Метрика | До | После | Экономия |
|---------|-----|--------|----------|
| **Папка** | 616.51 МБ | 158.95 МБ | **74.2%** |
| **ZIP** | 499.36 МБ | 268.08 МБ | **46.3%** |

## Что было удалено

### 1. `.vs/` папка (497 МБ)
- Кэш Visual Studio с IntelliSense индексами
- Временные файлы компилятора (`.ipch`, `.db`)
- Автоматически восстанавливается при открытии проекта

### 2. `x64/` папка (65 МБ)
- Скомпилированные объектные файлы (`.obj`)
- Debug символы (`.pdb`)
- Промежуточные файлы компиляции
- Пересоздаётся при каждой сборке

## ✅ Как избежать этого в будущем

### Уже настроено
`.gitignore` уже содержит все необходимые папки:
```
.vs/
x64/
[Dd]ebug/
[Rr]elease/
bin/
obj/
```

### Что делать при разработке
```bash
# 1. Не коммитьте build файлы
git status  # Проверьте что .vs и x64 не включены

# 2. При архивировании исключите папки
# (используйте GUI архиватора или командную строку)

# 3. Перед отправкой проверьте размер
ls -lh VisualEngine.zip
```

### Команда для создания чистого архива (PowerShell)
```powershell
# Удалить временные папки перед архивированием
Remove-Item -Path '.vs' -Recurse -Force
Remove-Item -Path 'x64' -Recurse -Force

# Создать архив
Compress-Archive -Path . -DestinationPath VisualEngine_clean.zip
```

## 🔄 После распаковки архива
1. Visual Studio автоматически пересоздаст `.vs/` папку
2. Первая сборка займёт чуть дольше
3. `x64/` папка будет создана при компиляции
